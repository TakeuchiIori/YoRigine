# プレイヤーカメラ：操作感の設計と改善計画

3Dアクションにおける追従カメラの「操作感（ゲームフィール）」を設計・改善するための資料。

---

## 1. システム構成

追従カメラを **Engine層（汎用）／Game層（ゲーム固有）** に分離している。

| 層 | クラス | 責務 |
|---|---|---|
| Engine | `FollowCamera` | 位置追従・スムージング・シェイク・ズーム・コリジョン回避・フレーミング |
| Game | `PlayerCamera` | スティック入力・ロックオン・攻撃カメラワーク・戦闘演出・気配察知 |
| 補助 | `CameraCollisionResolver` | 壁とのめり込み回避（pivot→camera のレイ） |

---

## 2. 実装済みの「操作感」要素（狙い）

- **追従スムージング**：臨界減衰スプリング（SmoothDamp）で理想位置へ滑らかに追従。瞬間スナップ閾値でテレポート対策。
- **速度先読み（look-ahead）**：移動速度に応じて注視点を進行方向へ先行させる＝予測カメラ。走行中に前方が見える。
- **フレーミング補正**：追従対象が画角端に来たら穏やかに引き戻し（NDCハードガードを後段に併設）。
- **コリジョン回避**：壁クリップ時にカメラを手前へ寄せる。
- **ロックオン2ショット**：肩オフセット＋見下ろしでプレイヤーと敵を重ねず縦に分離する。
- **気配察知**：視界外の敵の方向へ軽く首振り＋囲まれ時にFOV拡大（完全には固定しない）。
- **攻撃カメラワーク**：攻撃ごとにキーフレーム駆動でオフセット／注視／FOV／タイムスケールを再生。
- **見切れ演出**：画面外の敵を攻撃した瞬間、敵方向へ回り込み＋ズーム寄り＋シェイク＋ロックオン照準フラッシュ（赤→黄フェード）。

### 2.1 カメラ遮蔽ディザーフェード

プレイヤーとカメラの間に建物や木が入った場合、カメラを手前へ押し戻す代わりに遮蔽物をディザーで透明化できる。通常のアルファブレンドは使わず、ピクセルを確率的な閾値で間引くスクリーンドア透過を採用している。

#### 有効化

SceneEditorで対象オブジェクトのコライダーを有効にし、`カメラフェード`をONにする。設定は`PlacedObject::colliderCameraFade`としてシーンJSONへ保存される。「この設定を同名オブジェクト全てにコピー」、オブジェクト複製、コピー＆貼り付けでも引き継がれる。

対象コライダーのType IDは、`CameraCollisionResolver`の許可リスト（既定では`kStaticWall`と`kNavObstacle`）に含まれている必要がある。

#### 処理の流れ

1. `CameraCollisionResolver`がプレイヤーのpivotから理想カメラ位置へレイを飛ばす。
2. `CollisionManager::RaycastAllAllowTypes`がレイ上の全コライダーを距離順で返す。
3. `IsCameraFadeMode()`が有効な全コライダーを`FadeHit`として収集する。家と、その奥にある木など複数の遮蔽物を同時に扱える。
4. `PlayerCamera`が`PlacedObject*`ごとに現在のアルファ値を保持し、遮蔽中は目標値へ、レイから外れた後は`1.0`へ指数補間する。
5. `SceneEditor`がフェード中の静的モデルをディザー付きインスタンスとして通常の深度パスへ登録する。
6. `Object3dInstanced.PS.hlsl`が画面上のピクセル座標から固定ノイズ閾値を生成し、`clip()`でピクセルを間引く。

#### 透明度

- 遮蔽開始時の目標アルファは`occludeTargetAlpha_`（既定`0.25`）。
- カメラがコライダーへ侵入するほど`0.0`へ近づく。
- 侵入深度が`fullyTransparentDepth_`（既定`0.5`）以上になると完全透明になる。
- 透明化の追従速度は`occludeFadeInSpeed_`（既定`10.0`）、復帰速度は`occludeFadeOutSpeed_`（既定`7.0`）。いずれもフレームレート非依存の指数補間。

#### ディザーを使う理由

複雑な建物を通常のアルファブレンドで描くと、屋根・外壁・内部の面を奥から手前へ正しく並べる必要がある。並び順が不正確な場合、面が何重にも混ざってまだらに見える。ディザーでは残ったピクセルを不透明として描画し、深度書き込みも維持するため、この透明描画順問題を避けられる。

ディザーパターンは時間で動かさないため、静止中のチラつきは発生しない。フェード中は不透明なインバートハル輪郭だけが残らないよう、対象インスタンスの輪郭描画を無効にする。

#### 実装箇所

| 責務 | ファイル |
|---|---|
| 全ヒットレイキャスト | `YEngine/Utilities/Collision/Core/CollisionManager.{h,cpp}` |
| 遮蔽物の収集・目標アルファ計算 | `YEngine/Utilities/Systems/Camera/CameraCollisionResolver.{h,cpp}` |
| 複数遮蔽物の補間・復帰 | `YGame/GameObjects/Player/Camera/PlayerCamera.{h,cpp}` |
| ディザーインスタンス登録 | `YEngine/Graphics/Drawer/InstancedObject3d.{h,cpp}`、`YEngine/Generators/SceneEditor/SceneEditor.cpp` |
| ピクセル間引き | `Resources/Shaders/Object3d/Object3dInstanced.PS.hlsl` |
| エディタ設定・保存 | `SceneEditorUI.cpp`、`SceneSerializer.cpp`、`ObjectManager.{h,cpp}` |

#### 現在の制約

- ディザーパスはSceneEditorがインスタンシング描画する静的・非スキニングモデル向け。アニメーション付きモデルや特殊な個別描画オブジェクトへ適用する場合は、それぞれの描画シェーダーにも同等のディザーフラグと`clip()`処理が必要。
- 判定はpivot→cameraのレイ1本。画面上で大きな遮蔽物をより安定して検出したい場合は、将来的に球キャストまたは複数プローブへ拡張する。
- `PlayerCamera`はフェード前の基準アルファを`1.0`として復帰させる。常設の半透明素材とカメラフェードを併用する場合は、元アルファを別途保存する必要がある。

## 3. 改善計画（操作感の引き上げ・優先度順）

### A. 入力の素性【最優先・根幹】

現状の右スティック回転は「フレーム毎に固定量を加算／倒し量を正規化で破棄」。課題：

- **フレームレート非依存になっていない**（`× dt` 欠落）。毎フレーム固定量を加算するため、45–55fps と 60fps で回転速度が変わり、**実行環境ごとに操作感が変わる**。
- **アナログ精度が無い**（倒し量を正規化で捨てている）。フルスピードか0かで、ゆっくり狙えない。
- レスポンスカーブ・ラジアルデッドゾーン・感度別設定（ヨー/ピッチ）・加速（ramp）が無い。

→ **dt化 ＋ 倒し量反映 ＋ レスポンスカーブ（指数） ＋ ラジアルデッドゾーン ＋ 加速** で、精密かつ環境非依存にする。

### B. 距離・FOVのダイナミクス

- 速度連動のズームアウト／距離伸長（疾走感）。
- 戦闘では寄り、探索では引き、をスムーズに切り替え。
- ダッシュ／回避時のFOVキック（一瞬広げて戻す）。

### C. ヒット・衝撃フィードバック

- 打撃方向ベースのシェイク（無方向ランダム → 方向付き）で重みを出す。
- 大ヒット／パリィでの短いタイムスケール・ディップ（軽スロー）。
- 通常ヒットにも軽いマイクロズームパンチ。

### D. ロックオンの詰め

- ソフトロック／エイムアシスト（完全固定でなく狙う方向へ寄せる）。
- 距離・視線切れでの自動解除と復帰。
- ターゲット切替のフリック感度。

### E. コリジョン・復帰

- 壁回避をレイ1本 → 球（sphere）キャスト／複数プローブにしてポップ低減。
- 引き込み後のバネ復帰で戻りを滑らかに。

### F. 状態遷移

- Default／Battle／Cinematic 間にブレンド時間を設けてハードカットを排除。

### G. 味付け

- 待機時の微スウェイ（呼吸）、長時間無操作での緩い自動リセンター。
- 着地ディップ（地形・段差導入後）。

---

## 4. 優先着手：A（入力の素性）

- 全回転計算を **秒あたり** に統一（フレームレート非依存）。
- スティック倒し量 ＋ **レスポンスカーブ** で「精密〜素早い」を連続制御。
- **ラジアルデッドゾーン** で中央の遊びを自然に。
- 感度・カーブ指数・デッドゾーン・加速を **エディタ調整可** にし、実機で追い込む。
- 期待効果：**精密な視点操作** ＋ **異なる実行環境（3060 / 5070）で同一の操作感**。
